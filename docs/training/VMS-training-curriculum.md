# หลักสูตรอบรมการใช้งานระบบ VMS (Visitor Management System)

> **กลุ่มเป้าหมาย:** เจ้าหน้าที่ IT (ผู้ดูแลระบบ) และ เจ้าหน้าที่ของกรม (host / ผู้ใช้งาน)
> **ระยะเวลา:** แบ่งเป็น 2 ช่วงการอบรม — **ส่วนที่ 1 (Admin / IT) 90 นาที** และ **ส่วนที่ 2 (User / host) 25 นาที**

ระบบ VMS เป็นระบบบริหารจัดการผู้มาติดต่อ (Visitor Management) รองรับการทำงานหลายช่องทาง: เว็บสำหรับเจ้าหน้าที่, LINE Official Account สำหรับผู้มาเยือน, เครื่อง Kiosk บริการตนเอง และ Counter จุดบริการ

**Roles ในระบบ 5 ระดับ:**

| Role | ชื่อ | ขอบเขต | หน้าที่หลัก |
|------|------|--------|-------------|
| `visitor` | ผู้มาติดต่อ | เฉพาะของตนเอง | จองนัด, ดู QR, ติดตามสถานะ |
| `staff` | เจ้าหน้าที่ (host) | ระดับแผนก | สร้างนัด, อนุมัติ, ดูแลผู้มาเยือน |
| `supervisor` | หัวหน้า | ทุกแผนก | งานของ staff + blocklist + รายงานรวม |
| `security` | เจ้าหน้าที่ รปภ. | Counter/Kiosk | check-in/out, พิมพ์บัตร, walk-in |
| `admin` | ผู้ดูแลระบบ | ทั้งระบบ | ตั้งค่าและจัดการระบบทั้งหมด |

## ช่วงเปิด — ภาพรวมระบบ (5 นาที)

**วัตถุประสงค์:** ให้ผู้เรียนเห็นภาพรวมและเข้าใจ flow การทำงานหลักก่อนลงรายละเอียด

- แนะนำระบบ VMS และช่องทางการเข้าถึง (เว็บ / LINE / Kiosk / Counter)
- อธิบาย roles 5 ระดับ และใครรับผิดชอบอะไร
- **Flow หลักของผู้มาเยือน:** จองนัด (LINE/เว็บ) → เจ้าหน้าที่อนุมัติ → ผู้มาเยือนได้ QR → check-in ที่ Kiosk/Counter → ระหว่างอยู่ในอาคาร (WiFi/บัตร) → check-out

# ส่วนที่ 1 — Admin / IT: การ Setup และดูแลระบบ (90 นาที)

> **กลุ่มเป้าหมาย:** เจ้าหน้าที่ IT · **เมนู:** ตั้งค่า (Settings) — เข้าถึงได้เฉพาะ role `admin`
> **รูปแบบการสอน:** บรรยาย + สาธิตบนหน้าจอจริง (demo) + ให้ผู้เรียนลองทำตามในระบบทดสอบ (hands-on)

## 1.1 การจัดการผู้ใช้และสิทธิ์ (14 นาที)

**หน้าจอ:** ตั้งค่า → ผู้ใช้งาน (`settings/users`)

### หัวข้อย่อย
1. **โครงสร้างสิทธิ์ (role-based access) — 4 นาที**
   - อธิบาย 5 roles และขอบเขต (scope): `own` / `department` / `all`
   - หลักการให้สิทธิ์แบบ least privilege: ให้สิทธิ์เท่าที่จำเป็นต่อหน้าที่
   - ความแตกต่างระหว่างบัญชีเจ้าหน้าที่ (staff login) กับบัญชีผู้มาติดต่อ (visitor login)
2. **การสร้างและจัดการบัญชี — 6 นาที (demo + hands-on)**
   - สร้างบัญชีใหม่: username/email, ตั้ง role, ผูกกับเจ้าหน้าที่ในทำเนียบ
   - แก้ไขข้อมูล, เปลี่ยน role, ลบบัญชี
   - ล็อก / ปลดล็อกบัญชี (กรณีพนักงานลาออก/ย้าย), reset รหัสผ่าน
3. **บัญชี LINE และความปลอดภัย — 4 นาที**
   - ผูก / ยกเลิกการผูกบัญชี LINE
   - ตรวจสอบสถานะยืนยันอีเมล, การเข้าใช้งานล่าสุด (last login)
   - แนวทางจัดการบัญชี admin: จำกัดจำนวน, ทบทวนสิทธิ์เป็นระยะ

> **สิ่งที่ผู้เรียนต้องทำได้:** สร้างบัญชีให้เจ้าหน้าที่ใหม่พร้อม role ที่ถูกต้อง, ระงับบัญชีที่ไม่ใช้งาน และอธิบายได้ว่าแต่ละ role เห็น/ทำอะไรได้บ้าง

## 1.2 ตั้งค่า Master Data (22 นาที)

> Master Data เป็นรากฐานของทั้งระบบ — ต้องตั้งค่าก่อนเปิดใช้งานจริง และตั้งตามลำดับด้านล่างเพราะข้อมูลอ้างอิงต่อกัน

### 1.2.1 สถานที่ — อาคาร / ชั้น / แผนก (5 นาที)
**หน้าจอ:** `settings/locations`
- สร้างโครงสร้างลำดับชั้น: อาคาร → ชั้น → แผนก
- ความสำคัญ: ใช้อ้างอิงในนัดหมาย, การกำหนดเจ้าหน้าที่ และรายงานแยกแผนก
- ข้อควรระวัง: ตั้งชื่อให้เป็นมาตรฐานเดียวกันทั้งกรม

### 1.2.2 วัตถุประสงค์เข้าพบ (Visit Purposes) (6 นาที)
**หน้าจอ:** `settings/visit-purposes`
- กำหนดประเภทการเข้าพบ (ติดต่อราชการ, ประชุม, ส่งของ, ผู้รับเหมา ฯลฯ)
- **กำหนดช่องทางที่แสดง** (channel visibility): LINE / Web / Kiosk / Counter — ควบคุมว่าแต่ละวัตถุประสงค์ให้จองผ่านช่องทางใดได้
- เลือกโหมดการลงทะเบียน: รายเดี่ยว (single) หรือแบบกลุ่ม (batch)
- ผูกวัตถุประสงค์กับแผนกที่รับผิดชอบ

### 1.2.3 ประเภทเอกสารและการยืนยันตัวตน (4 นาที)
**หน้าจอ:** `settings/document-types`
- กำหนดประเภทเอกสาร: บัตรประชาชน, Passport, Visa, Work Permit
- ตั้งเงื่อนไข **บังคับ/ไม่บังคับ** ต่อแต่ละวัตถุประสงค์, กำหนดให้ต้องถ่ายรูปเอกสารหรือไม่
- จัดลำดับการแสดง และเปิด/ปิดการใช้งาน

### 1.2.4 ทำเนียบเจ้าหน้าที่ (Staff Directory) (4 นาที)
**หน้าจอ:** `settings/staff`
- เพิ่ม/แก้ไขข้อมูลพนักงาน: ชื่อ, แผนก, ตำแหน่ง, สถานะใช้งาน
- ผูกบัญชี LINE ของเจ้าหน้าที่ (สำหรับรับแจ้งเตือน/อนุมัติผ่านมือถือ)
- ความเชื่อมโยง: เจ้าหน้าที่ในทำเนียบคือ "ผู้ถูกนัดพบ (host)" ที่ผู้มาเยือนเลือกตอนจอง

### 1.2.5 โซนการเข้าถึง (Access Zones) (3 นาที)
**หน้าจอ:** `settings/access-zones`
- กำหนดพื้นที่เข้าถึงทางกายภาพ และ map เข้ากับอาคาร/ชั้น
- การเชื่อมต่อระบบประตู **Hikvision** (access control) — กรณีหน่วยงานใช้ควบคุมประตูจริง

> **สิ่งที่ผู้เรียนต้องทำได้:** ตั้งค่า master data ครบทั้ง 5 ชุดตามลำดับ และอธิบายได้ว่าการตั้งค่าวัตถุประสงค์/ช่องทาง ส่งผลต่อสิ่งที่ผู้มาเยือนเห็นบน LINE/Kiosk อย่างไร

## 1.3 Workflow การอนุมัติ (12 นาที)

**หน้าจอ:** ตั้งค่า → กลุ่มผู้อนุมัติ (`settings/approver-groups`)

### หัวข้อย่อย
1. **แนวคิด workflow การอนุมัติ — 3 นาที**
   - เส้นทางคำขอ: ผู้มาเยือนจอง → ระบบส่งให้กลุ่มผู้อนุมัติที่ผูกกับวัตถุประสงค์ → อนุมัติ/ปฏิเสธ → แจ้งผู้มาเยือน
2. **สร้างและจัดการกลุ่มผู้อนุมัติ — 6 นาที (demo + hands-on)**
   - สร้างกลุ่ม, เพิ่มสมาชิก (เลือกจากทำเนียบเจ้าหน้าที่)
   - กำหนดสิทธิ์การอนุมัติของสมาชิกแต่ละคน
   - ผูกกลุ่มเข้ากับวัตถุประสงค์การเข้าพบ — จุดสำคัญที่ทำให้คำขอวิ่งไปถูกคน
3. **ช่องทางแจ้งเตือนของกลุ่ม — 3 นาที**
   - กำหนดให้แจ้งผู้อนุมัติทาง Email / LINE / SMS
   - ข้อแนะนำ: ใช้ LINE สำหรับการตอบสนองเร็ว, Email สำหรับเก็บหลักฐาน

> **สิ่งที่ผู้เรียนต้องทำได้:** ออกแบบและตั้งค่ากลุ่มผู้อนุมัติให้คำขอแต่ละประเภทถูกส่งไปยังผู้รับผิดชอบที่ถูกต้อง พร้อมแจ้งเตือนตามช่องทางที่เหมาะสม

## 1.4 อุปกรณ์และจุดบริการ (15 นาที)

**หน้าจอ:** ตั้งค่า → จุดบริการ (`settings/service-points`), เวลาทำการ (`settings/business-hours`)

### 1.4.1 ลงทะเบียนเครื่อง Kiosk / Counter (7 นาที)
- ลงทะเบียนอุปกรณ์: ระบุ IP, MAC, Serial number
- ตั้งค่า WiFi credentials สำหรับเครื่อง และ **PIN สำหรับ admin** เข้าหน้าตั้งค่าเครื่อง
- กำหนดการขอความยินยอม PDPA ที่เครื่อง
- ความแตกต่าง: **Kiosk** = บริการตนเอง (self-service), **Counter** = มีเจ้าหน้าที่ รปภ. ช่วยดำเนินการ

### 1.4.2 ตรวจสอบสถานะและดูแลอุปกรณ์ (4 นาที)
- ตรวจสอบสถานะออนไลน์/ออฟไลน์ของแต่ละเครื่อง
- การ troubleshoot เบื้องต้นเมื่อเครื่องหลุดการเชื่อมต่อ (network, card reader, printer)
- ความเชื่อมโยงกับอุปกรณ์ต่อพ่วง: เครื่องอ่านบัตร, เครื่องอ่าน passport, เครื่องพิมพ์ thermal, กล้องถ่ายรูปใบหน้า

### 1.4.3 เวลาทำการและวันหยุด (4 นาที)
**หน้าจอ:** `settings/business-hours`
- ตั้งเวลาเปิด-ปิดทำการ และกำหนดวันหยุด/วันหยุดนักขัตฤกษ์
- เงื่อนไขอนุญาต walk-in หรือใช้ Kiosk ในแต่ละวัน
- สร้างกฎตามช่วงเวลา (period-based rules)

> **สิ่งที่ผู้เรียนต้องทำได้:** ลงทะเบียนและกำหนดค่าเครื่อง Kiosk/Counter ใหม่ได้ครบ, ตรวจสอบสถานะอุปกรณ์ และตั้งเวลาทำการให้สอดคล้องกับการเปิดให้บริการจริง

## 1.5 การแจ้งเตือนและ Integration (14 นาที)

> ส่วนนี้เป็นงาน IT ล้วน ต้องอาศัยข้อมูลจากผู้ให้บริการ (SMTP, LINE Developers) — ควรเตรียมค่าก่อนการอบรม

### 1.5.1 ตั้งค่าอีเมล SMTP (4 นาที)
**หน้าจอ:** `settings/email-system`
- กรอก server, port, encryption (TLS/SSL), ผู้ส่ง (address/name)
- **ทดสอบส่งอีเมลจริง** เพื่อยืนยันการตั้งค่า
- ปัญหาที่พบบ่อย: port/firewall, app password, การ block จากผู้ให้บริการ

### 1.5.2 ตั้งค่า LINE Official Account (6 นาที)
**หน้าจอ:** `settings/line-oa-config`
- กรอก Channel ID / Channel Secret / Access Token (จาก LINE Developers Console)
- ตั้งค่า LIFF endpoint (หน้าจองสำหรับผู้มาเยือนบนมือถือ)
- จัดการ rich menu สำหรับผู้มาเยือนและเจ้าหน้าที่
- **ทดสอบ webhook** เพื่อยืนยันการเชื่อมต่อ

### 1.5.3 เทมเพลตข้อความแจ้งเตือน (4 นาที)
**หน้าจอ:** `settings/notification-templates`, `settings/line-message-templates`
- เทมเพลตตาม event: สร้างนัด / อนุมัติ / ปฏิเสธ / check-in (รองรับ TH/EN)
- ออกแบบ LINE Flex message: หัวข้อ, ฟิลด์ข้อความ, ปุ่ม, ค่าตัวอย่าง (preview)
- การใช้ตัวแปร (template variables) เช่น ชื่อผู้มาเยือน, วันเวลานัด

> **สิ่งที่ผู้เรียนต้องทำได้:** เชื่อมต่ออีเมลและ LINE OA จนทดสอบส่งได้สำเร็จ และปรับแต่งข้อความแจ้งเตือนให้ตรงกับรูปแบบของหน่วยงาน

## 1.6 PDPA และเทมเพลตบัตร/ใบนัด (8 นาที)

### 1.6.1 การจัดการความยินยอม PDPA (5 นาที)
**หน้าจอ:** `settings/pdpa-consent`
- กำหนดข้อความนโยบายความเป็นส่วนตัว (TH/EN)
- ตั้ง **ระยะเวลาเก็บข้อมูล** (data retention) ตามนโยบายหน่วยงาน
- บังคับให้เลื่อนอ่านจนจบก่อนยินยอม, จัดการเวอร์ชันของ consent
- ตรวจสอบ log การให้ความยินยอม (consent log) — สำคัญด้านการตรวจสอบย้อนหลัง

### 1.6.2 เทมเพลตบัตร / ใบนัด (3 นาที)
**หน้าจอ:** `settings/visit-slips`
- ออกแบบเทมเพลตบัตรผู้มาเยือน: ขนาดกระดาษ (thermal / A4), โลโก้หน่วยงาน
- เปิด/ปิดส่วนที่แสดง: ข้อมูลผู้มาเยือน, QR code, ชื่อ host
- ดูตัวอย่างก่อนพิมพ์ (print preview)

> **สิ่งที่ผู้เรียนต้องทำได้:** ตั้งค่า PDPA ให้สอดคล้องกับนโยบายและกฎหมาย และออกแบบบัตรผู้มาเยือนให้พร้อมพิมพ์ใช้งานจริง

# ส่วนที่ 2 — User (host): การใช้งานประจำวัน (25 นาที)

> **กลุ่มเป้าหมาย:** เจ้าหน้าที่ของกรม (staff / supervisor) · ใช้งานผ่านเว็บ และแอปมือถือ (officer)

## 2.1 เข้าสู่ระบบ และอ่าน Dashboard (3 นาที)

**หน้าจอ:** `dashboard`, `profile`

- เข้าสู่ระบบ และจัดการข้อมูลส่วนตัว (เปลี่ยนรหัสผ่าน, ผูก LINE)
- อ่านค่าสรุปประจำวัน: จำนวนผู้มาเยือน, นัดหมาย, walk-in, check-in/out, การแจ้งเตือนเกินเวลา (overstay)

## 2.2 การสร้างและจัดการนัดหมาย (8 นาที)

**หน้าจอ:** นัดหมาย (`appointments`), นัดหมายแบบกลุ่ม (`appointments/groups`)

**สิ่งที่ผู้เรียนต้องทำได้:**
- สร้างนัดหมายเดี่ยว: ข้อมูลผู้มาเยือน, เจ้าหน้าที่ที่เข้าพบ, วัตถุประสงค์, วัน-เวลา, ผู้ติดตาม
- สร้างนัดหมายแบบกลุ่ม (สำหรับคณะดูงาน): กำหนดช่วงวัน/รอบเวลา, นำเข้ารายชื่อจาก Excel, ผูกกลุ่มผู้อนุมัติ
- แก้ไข / ยกเลิกนัด, ติดตามสถานะ, พิมพ์หรือส่ง QR ให้ผู้มาเยือน

## 2.3 การอนุมัติคำขอ (5 นาที)

**หน้าจอ:** คิวอนุมัติเว็บ (`approvals`), แอปมือถือ (`mobile/officer/requests`)

- ดูคำขอที่รออนุมัติ, กรองตามสถานะ (รออนุมัติ/อนุมัติ/ปฏิเสธ/ดำเนินการ)
- อนุมัติ / ปฏิเสธพร้อมระบุเหตุผล และระบบแจ้งเตือนผู้มาเยือนอัตโนมัติ
- ทำงานได้ทั้งบนเว็บและบนมือถือ (officer app) สำหรับอนุมัตินอกสถานที่

## 2.4 การดูแลผู้มาเยือนระหว่างวัน (4 นาที)

**หน้าจอ:** `mobile/officer/hospitality`

- ติดตามรายชื่อผู้มาเยือนที่อยู่ในอาคารขณะนั้น
- จ่ายข้อมูล WiFi, จัดการผู้ติดตาม, ตรวจสอบเวลา check-in / check-out

## 2.5 ค้นหา ประวัติ และรายงาน (3 นาที)

**หน้าจอ:** ค้นหา (`search`), รายงาน (`reports`)

- ค้นหาผู้มาเยือนด้วยชื่อ/เลขบัตร/บริษัท และดูประวัติการเข้าออก
- ดูรายงานสถิติรายวัน, แยกตามวัตถุประสงค์และแผนก, กรองตามช่วงวันที่

## 2.6 Blocklist และข้อควรระวัง (2 นาที)

**หน้าจอ:** `blocklist` *(เฉพาะ supervisor / admin)*

- เพิ่ม / ถอนรายชื่อ blocklist พร้อมเหตุผลและวันหมดอายุ (ถาวร/ชั่วคราว)
- ข้อควรระวังด้าน PDPA และการรักษาความลับข้อมูลผู้มาเยือน

---

> **ช่วงปิดส่วนที่ 2 (รวมในเวลา):** ตอบข้อสงสัย, แจ้งช่องทางขอความช่วยเหลือ (ผู้ดูแลระบบของหน่วยงาน), สรุปสิ่งที่ต้องเตรียมก่อนเริ่มใช้งานจริง

# ภาคผนวก ก — Checklist สำหรับ IT (ลำดับการตั้งค่าก่อนเปิดใช้งาน)

ตั้งค่าตามลำดับเพื่อให้ข้อมูลอ้างอิงกันครบถ้วน:

1. ☐ สถานที่ — อาคาร / ชั้น / แผนก (`settings/locations`)
2. ☐ ทำเนียบเจ้าหน้าที่ (`settings/staff`)
3. ☐ บัญชีผู้ใช้และ role (`settings/users`)
4. ☐ วัตถุประสงค์เข้าพบ + ช่องทางที่แสดง (`settings/visit-purposes`)
5. ☐ ประเภทเอกสาร (`settings/document-types`)
6. ☐ กลุ่มผู้อนุมัติ + ผูกวัตถุประสงค์ (`settings/approver-groups`)
7. ☐ โซนการเข้าถึง / Hikvision (`settings/access-zones`)
8. ☐ เวลาทำการ / วันหยุด (`settings/business-hours`)
9. ☐ จุดบริการ Kiosk / Counter (`settings/service-points`)
10. ☐ อีเมล SMTP + ทดสอบส่ง (`settings/email-system`)
11. ☐ LINE OA + ทดสอบ webhook (`settings/line-oa-config`)
12. ☐ เทมเพลตแจ้งเตือน + เทมเพลต LINE (`settings/notification-templates`, `settings/line-message-templates`)
13. ☐ PDPA consent (`settings/pdpa-consent`)
14. ☐ เทมเพลตบัตร / ใบนัด (`settings/visit-slips`)

# ภาคผนวก ข — Quick Reference สำหรับ User (host)

| ต้องการทำ | ไปที่ |
|-----------|-------|
| ดูสรุปวันนี้ | Dashboard |
| สร้างนัดให้ผู้มาติดต่อ | นัดหมาย → สร้างนัด |

| ดูใครอยู่ในอาคาร / จ่าย WiFi | แอป officer → Hospitality |
| ค้นหาผู้มาเยือน / ประวัติ | ค้นหา |
| ดูรายงานสถิติ | รายงาน |
| จัดการ blocklist *(หัวหน้า)* | Blocklist |
